# 知识库维护说明

## 基本原则

1. 已发布菜谱不可原地覆盖。需要修改时新增更高版本，例如 `v2.md`。
2. Obsidian 文件名和双向链接服务于人；`recipe_id`、`ingredient_id`、版本和状态服务于 MCP。
3. 食材替换是“带上下文的规则”，必须说明适用菜谱/角色、步骤变化、过敏原变化和依据。
4. `alternative_to` 只表示可作为整菜候选，不表示价格一定更低。预算换菜必须重新汇总采购并报价。
5. 新内容先设为 `draft`；经过结构校验和人工审核后再改为 `published`。
6. 正文必须包含三个非空章节：`## 做法`、`## 替换建议`、`## 储存与安全`，缺一个都会在 `validate` 时报错。

## 食材的角色标注（V0.5）

`ingredients[]` 每项可以选填三个字段，`role`/`optional`/`defines_dish`（复用 `substitutions/` 已有的角色枚举）。不确定就不填，不要瞎猜——缺失时系统会保守跳过，不会当成默认值处理：

- `role`：`primary`（主料）| `supporting`（配料）| `seasoning`（调味）| `garnish`（点缀）| `cooking_medium`（油/介质）。
- `optional`：这个食材能不能整体不放。
- `defines_dish`：换掉/去掉这个食材，还算不算同一道菜。`true` 的食材缺货时，`find_replacements` 只会给"换成别的菜"的候选，不会假装成"稍微调整一下"；换法应该走 `relations/` 的 `variant_of`，不是 `substitutions/`。

参考 `recipes/tomato-eggs/番茄炒蛋-v2.md`、`recipes/smashed-cucumber/拍黄瓜-v2.md` 这两篇已经标注过的菜谱。其余菜谱还没补，缺失不影响正常使用，想起来了再补，不用一次性做完。

## 新建菜谱

1. 在 Obsidian 里新建笔记，`Ctrl/Cmd+P → Insert template` 插入 `templates/recipe-template.md`。
2. 按模板填写 frontmatter 和三段正文，`status` 先保持 `draft`。
3. `npm run recipe -- validate` 确认 schema、三段式正文和引用都通过。
4. `npm run recipe -- create-draft <文件路径>` 把内容规范化进 `drafts/` 并确定版本号。
5. `npm run recipe -- publish <recipe_id> <version>` 发布为不可变版本（会自动跑过敏原复核）。

## 新增内容后的检查

- `npm run recipe -- validate`
- `npm test`
- 确认 Obsidian 中的双向链接没有指向错误版本。

## 关系的选择

- 食材买不到：优先建 `substitutions/` 规则；若做法整体不再成立，再建 `alternative_to`。
- 想控制预算：建候选关系，不写静态“便宜”结论；运行时用采购量和当期报价比较。
- 想复用余料：使用 `uses_leftover_from`，并在原因中说明可复用的标准食材 ID。
- 想补全一餐：使用 `pairs_with`，但所有入选菜仍要进入采购汇总和校验。
