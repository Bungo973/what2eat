# MCP 连接说明

这份文件只处理"怎么判断连上了、没连上时怎么办"，不改变平台无关的菜谱规划和数据规则（见 [平台无关行为规范](meal-planning.md)）。适用于任何 Agent 宿主，不针对某一个特定宿主写。

## 服务地址

```
https://mcp.aobiwan.icu/mcp
```

这个地址可以公开告诉任何使用这份 Skill 的人。**访问需要一个 Bearer Token，这个不包含在这份 Skill 里**，需要向把这份 Skill 分享给你的人单独索取——不要猜测、编造或复用其他项目的凭证。

## 怎么判断有没有连上

不同宿主可能把工具名原样暴露，也可能自动加一个命名空间前缀（比如把 `search_recipes` 变成 `xxx_search_recipes`）。判断规则：

1. 收到第一个需要工具执行的具体菜谱需求后，首次调用前先查看宿主实际暴露的工具列表。
2. 优先匹配与下面规范名完全相同的可调用标识符；找不到就找宿主暴露的、以 `_<规范名>` 结尾的唯一候选，把规范名绑定到这个实际返回的名字。
3. 描述工具和调用工具都用列表返回的精确名称，绑定之后同一次任务内复用，不要在裸名和加前缀的名字之间来回试探。
4. 同一个规范名同时匹配到多个候选（歧义）时，停止调用并如实报告，不要猜一个用。
5. 报错是 `tool_not_found` 且错误信息里给出了唯一的命名空间候选时，改用建议的完整名称重试一次；仍然找不到，判定为未连接。

八个规范工具名：`search_recipes`、`grep_recipe_docs`、`read_recipe`、`aggregate_shopping_list`、`validate_meal_plan`、`quote_ingredient_prices`、`find_replacements`、`render_meal_plan_html`。

## 没连上时怎么办

按顺序处理，每一步都不要跳：

1. **告诉用户地址**：`https://mcp.aobiwan.icu/mcp`，说明需要一个 Token，请用户去问把这份 Skill 给他的人要。在拿到 Token 之前不要继续往下走，也不要用模型记忆假装已经连上、编造菜谱或价格结果。
2. **拿到 Token 后，判断自己（当前运行的 Agent）有没有文件读写或命令执行能力**：
   - **有**（比如能读写宿主的本地配置文件、能执行 shell 命令）：把打算写入的具体文件路径和内容、或者打算执行的具体命令，原样告诉用户，**得到明确确认后再执行**——这是标准配置变更，不能因为技术上做得到就跳过确认这一步。配置内容只包含地址和"这里需要一个 Token"的占位标记，实际值由用户自己提供或确认，你不主动把 Token 打进日志、多余的确认文本或任何非配置本身的位置。

     Claude Code 场景下常见的配置形状举例（不同版本可能有出入，写入前请用户确认路径和内容是否符合当前实际情况）：

     ```json
     {
       "mcpServers": {
         "meal-planning": {
           "type": "http",
           "url": "https://mcp.aobiwan.icu/mcp",
           "headers": {
             "Authorization": "Bearer <用户提供的 Token>"
           }
         }
       }
     }
     ```

   - **没有**：把上面这段配置（或对应宿主的等价形式）整理成代码块交给用户，明确告诉用户去哪个设置界面或哪个配置文件里自己粘贴，不代劳。
3. **配置完成后**：提醒用户可能需要重启或重新连接宿主的 MCP 会话，然后重新执行"怎么判断有没有连上"这一节的检查；确认能找到八个工具后，再回到正常流程处理用户最初的需求。

## 硬约束

- 不自行假设、猜测或启动一个 MCP 服务；普通菜谱请求不得擅自重启或修改已有连接。
- 工具不可见、连接被拒绝，或上面的配置流程走不通时，停止依赖该工具的步骤并如实告诉用户，不要用模型记忆替代知识库、价格或校验结果。
- 任何时候都不读取、不回显、不记录用户的 Token；Token 的保存和传递方式由宿主自己的凭证机制决定，这份 Skill 只负责告诉用户"需要一个"和"填在哪"。
